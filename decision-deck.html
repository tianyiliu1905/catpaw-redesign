编号用户目标 / 当前阻碍设计手段 / 如何解除阻碍
S1
用户想开始分析一时写不出完整需求，需要先选一个方向。

S2
用户想知道结果缺少报告样例，无法判断这项任务值不值得发起。
成品倒推需求：先预览报告，再看产物类型、技能与完整需求；“做同款”回填输入。3.1.2 · 检查：能指出预期产物并改写示例需求
S3
用户想补充材料入口太多，难预判点击后是添加内容还是更改设置。
结果导向分组：文件／技能／目标贴近输入；专家／连接器按需选择，归属与访问设置下挂。3.1.3 · 检查：点击前能说出去向；风险设置照常提示
S4
用户想顺畅探索首页和任务区的视觉语法需要一致。
视觉系统：语义 token、圆润图标与留白贯穿两处；明暗主题可切换并保存。3.1.4 · 检查：跨页面识别同类入口与产物类型

策略 3.2 / DECISION → ACTION · WAIT

把运行过程翻译成下一步行动。

用户目标 · 知道分析进度、补充价格要求、遇到异常时选择下一步。方法亮点 · 进展贴轮次、状态说任务语言、队列区分发送状态。

编号用户目标 / 当前阻碍设计手段 / 如何解除阻碍
W1
用户想回看本轮进展过程浮在输入上方，和发起任务的对话断开。
轮次归位：子 Agent 与进度放在最新轮次，默认收起、原位展开；持续目标留摘要。3.2.1 · 检查：进展能对上本轮消息
W2
用户想决定继续等或介入工具调用名称无法直接说明任务做到哪。
进展翻译：交代已完成、正在做、下一步；失败先说影响与选项，日志按需展开。3.2.2 · 检查：用户能复述当前阶段，不展示虚构预估
W3
用户想补充价格重点要知道新要求尚未发送，也要区分子 Agent 与主任务。
状态分层：队列贴输入、可编辑移除；发送后才生成轮次。侧栏缩进表达归属，右侧单一状态位。3.2.1 / 3.2.3 · 检查：能分清待发送、已发送与子任务
